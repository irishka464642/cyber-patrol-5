# 💬 Спілкування онлайн — інтерактивні вправи для 5 класу

Навчальні вправи до уроку **«Спілкування в інтернеті. Етикет спілкування в мережі. Безпечне використання інтернету»** (10.11.2026, 5-Б клас).

## Вправи
1. 💬 Етикет у чаті — правила мережевого етикету.
2. 🧠 Як відповісти? — безпечна комунікація.
3. 🗳️ Сторінка голосування — перевірка адреси та ознак фішингу на імітації сайту.
4. 📱 Месенджер і Threads — відповідь, блокування, скарги на спам та хейт.
5. ⚙️ Цифрові налаштування — дозволи таксі, приватність соцмереж і публікація фотографій.

15 інтерактивних дій (у перших двох вправах запитання, далі моделювання вебсторінки, чату й налаштувань), 1 бал за кожну правильну дію з першої спроби, пояснення після кожного вибору. Результати локальні до підключення Apps Script. Після підключення й натискання кнопки відправляються до Google Таблиць учителя.

> Усі сайти, повідомлення, конкурс і перемикачі всередині вправ є симуляціями: жодного реального голосування, надсилання повідомлень або зміни налаштувань акаунтів не відбувається. Для прикладу фейкового сайту використано домен `.example`, який не веде на справжній ресурс.

## Як опублікувати на GitHub Pages
1. Відкрити **Settings → Pages** у репозиторії.
2. У розділі **Build and deployment → Source** вибрати **Deploy from a branch**.
3. Вибрати **main** і **/(root)**, натиснути **Save**.
4. Після публікації сторінка має бути доступна за адресою **https://irishka464642.github.io/cyber-patrol-5/**.

## Використання на уроці
Учні можуть працювати самостійно або в парах. Орієнтовно 15–20 хвилин. Після виконання обговоріть, чому певні відповіді були небезпечними. Для повторення натисніть **«Пройти ще раз»**.

## Технічно
Застосунок — один файл `index.html`, HTML + CSS + JavaScript без сторонніх залежностей, адаптивний до телефонів та комп'ютерів. Працює без акаунтів і без аналітики.


## Автоматичний журнал 5 класу — підключення

Створено шість окремих Google Таблиць: 5-А, 5-Б і 5-В — для кожного класу групи 1 і 2. Усі вони в папці [5 клас](https://drive.google.com/drive/folders/1H-0ApDhivvneYLLZXJYbXvQfZMxJemqg). Код приймача: [apps-script/Code.gs](apps-script/Code.gs).

### Одноразові дії вчителя
1. Відкрити [script.google.com](https://script.google.com/) під Google-акаунтом, якому належать шість таблиць, та створити **Новий проєкт**.
2. Видалити початковий код із `Code.gs`, вставити вміст файлу `apps-script/Code.gs` з репозиторію й зберегти.
3. Обрати **Розгорнути → Нове розгортання → Вебзастосунок**. Виконувати від імені: **Я**. Доступ: **Усі (Anyone)**. Надати дозволи для роботи з Google Таблицями.
4. Скопіювати URL вебзастосунку, який закінчується на `/exec`.
5. У файлі `index.html` замінити `const RESULTS_ENDPOINT="";` на `const RESULTS_ENDPOINT="https://script.google.com/macros/s/ВАШ_ID/exec";` (або надіслати URL асистенту, щоб він зробив це в GitHub).
6. Після оновлення сайту виконати тест із вигаданими даними та перевірити, що у відповідній таблиці на вкладці **Результати** з'явилося **5 рядків**.

### Що записується
Дата, клас, група, прізвище, ім'я, назва вправи, бали з 3, номер спроби та час відповіді у секундах. Суму балів /15 легко отримати підсумовуванням п'яти рядків.

**Важливо:** наразі кнопка автоматичного надсилання видима, але неактивна, доки не вказано URL розгорнутого вебзастосунку. Після активації надсилання Google Apps Script через `no-cors` не дає сторінці достовірно підтвердити успішний запис, тому необхідно перевірити тестову таблицю. Не давайте URL учням, поки тест не пройдено. Цей endpoint доступний з інтернету, тому він не є захищеним від навмисних підроблених відповідей; результати слід вважати навчальними, не автентифікованими записами.

### Месенджер: інтерактивний сценарій

Четверта вправа тепер є симуляцією переписки, а не тестом. У чаті можна відкрити меню **⋮**, вибрати «Поскаржитися на спам/образи» та «Заблокувати контакт». В інших сценаріях можна надіслати безпечну відповідь або підтримку. У ситуаціях із двома необхідними діями бал нараховується після виконання обох; помилкова небезпечна дія позбавляє бала за цю ситуацію. Всі дії локальні, реальні повідомлення та скарги не надсилаються.


### Цифрові налаштування: три практичні сценарії

П'ята вправа більше не складається з трьох однотипних перемикачів. Учні налаштовують: (1) дозволи застосунку таксі — геолокація лише під час користування, без доступу до контактів, мікрофона й галереї; (2) навчальну імітацію Instagram — нікнейм, приховані персональні дані, приватний профіль; (3) допис про похід — згода друзів, відсутність точної геомітки, публікація після повернення та обмежена аудиторія. За безпомилкове виконання всіх налаштувань у кожній ситуації нараховується 1 бал. Сторінка не запитує реальних паролів і не змінює справжні акаунти.

Третя ситуація четвертої вправи відтворює стрічку коментарів під постом про гейміфікацію в «Мрії». Авторка `@marta.study` просить пояснити, як заробляти та використовувати Мрійки. За обидві безпечні дії без підтримки хейту нараховується 1 бал. Усі нікнейми, коментарі й дії вигадані; ця симуляція не пов'язана з Threads і нічого туди не надсилає.

### Підключення приймача результатів — 13.11.2026

До `index.html` додано надану адресу Apps Script `/exec`. **Початок учнівських вправ розблоковано після підтвердження вчителем реального тестового запису**, доки реальний тестовий запис не буде знайдений у відповідній Google Таблиці — формат URL і сам `fetch(..., mode: "no-cors")` не доводять успіх запису.

Створена окрема [сторінка тестування підключення](connection-test.html) **для вчителя**. Вона надсилає один тестовий результат до вибраного журналу (5 рядків `ТЕСТ ПЕРЕВІРКА`); потрібно перевірити його появу на вкладці `Результати`. Тільки тоді змінити `resultsConnectionVerified` у `index.html` з `false` на `true`. Після тесту прибрати контрольні записи з журналів. Потрібно також перевірити права доступу до вебзастосунку в приватному вікні браузера.


### 13.11.2026 — контрольний запис підтверджено

Вчитель повідомив, що тестові рядки надійшли в Google Таблицю й уже були видалені. У `index.html` виставлено `resultsConnectionVerified=true`: учнівська вправа розблокована. Зверніть увагу: `fetch(mode: "no-cors")` підтверджує лише надсилання запиту, не успіх запису кожної окремої роботи; для майбутніх сеансів рекомендований періодичний контроль журналу.
